Dew uses a schema-first approach. You define a Go struct (the model) and a schema variable that maps struct fields to typed columns.

## Model

A model is a plain Go struct. Fields are mapped to columns using struct tags.

```go
type User struct {
    ID    int    `db:"id"`
    Name  string `db:"name"`
    Email string `db:"email"`
    Age   int    `db:"age"`
}
```

### Struct tags

Dew checks tags in this order: `db` → `sql` → auto snake_case.

| Tag | Effect |
|-----|--------|
| `` `db:"column_name"` `` | Use `column_name` |
| `` `db:"-"` `` | Skip this field |
| `` `sql:"column_name"` `` | Fallback if no `db` tag |
| *(no tag)* | Auto-converts `FieldName` → `field_name` |

## DefineSchema

`DefineSchema` creates a schema variable with typed columns.

```go
var Users = dew.DefineSchema("users", dew.PostgreSQLDialect{}, func(t dew.Table[User]) struct {
    dew.Table[User]
    ID    dew.IntColumn
    Name  dew.StringColumn
    Email dew.StringColumn
    Age   dew.IntColumn
} {
    return struct {
        dew.Table[User]
        ID    dew.IntColumn
        Name  dew.StringColumn
        Email dew.StringColumn
        Age   dew.IntColumn
    }{
        Table: t,
        ID:    t.IntColumn("id"),
        Name:  t.StringColumn("name"),
        Email: t.StringColumn("email"),
        Age:   t.IntColumn("age"),
    }
})
```

The schema embeds `dew.Table[User]`, which gives you `Users.From(db)`, `Users.Insert(db)`, etc.

## Column types

| Method | Type | Go type |
|--------|------|---------|
| `t.IntColumn("name")` | `IntColumn` | `int` |
| `t.Int64Column("name")` | `Int64Column` | `int64` |
| `t.StringColumn("name")` | `StringColumn` | `string` |
| `t.BoolColumn("name")` | `BoolColumn` | `bool` |
| `t.FloatColumn("name")` | `FloatColumn` | `float64` |
| `t.Float32Column("name")` | `Float32Column` | `float32` |
| `t.TimeColumn("name")` | `TimeColumn` | `time.Time` |
| `t.UUIDColumn("name")` | `UUIDColumn` | `string` |
| `t.BytesColumn("name")` | `BytesColumn` | `[]byte` |
| `t.AnyColumn("name")` | `AnyColumn` | `any` |
| `dew.DefineEnumColumn[T](t, "name")` | `EnumColumn[T]` | `~string` |

For JSONB columns, see [JSONB](/docs/jsonb).

<Callout type="info">
Use `Int64Column` for `bigserial` / `bigint` primary keys and large counters. Use `AnyColumn` as an escape hatch for types dew doesn't cover natively — all its methods accept `any`. Use `EnumColumn` for string-based enum types — it gives you compile-time safety by restricting values to your custom type.
</Callout>

### EnumColumn

`EnumColumn` is generic over any `~string` type. Since Go doesn't allow type parameters on methods, use the standalone `DefineEnumColumn` function:

```go
type Status string

const (
    StatusActive  Status = "active"
    StatusBanned  Status = "banned"
    StatusPending Status = "pending"
)

var Users = dew.DefineSchema("users", dew.PostgreSQLDialect{}, func(t dew.Table[User]) struct {
    dew.Table[User]
    ID     dew.IntColumn
    Name   dew.StringColumn
    Status dew.EnumColumn[Status]
} {
    return struct {
        dew.Table[User]
        ID     dew.IntColumn
        Name   dew.StringColumn
        Status dew.EnumColumn[Status]
    }{
        Table:  t,
        ID:     t.IntColumn("id"),
        Name:   t.StringColumn("name"),
        Status: dew.DefineEnumColumn[Status](t, "status"),
    }
})
```

```go
// Type-safe — only accepts Status values
Users.From(db).Where(Users.Status.Eq(StatusActive))
Users.From(db).Where(Users.Status.In(StatusActive, StatusPending))

// Won't compile:
Users.From(db).Where(Users.Status.Eq("random"))
```

`EnumColumn` supports: `Eq`, `NotEq`, `In`, `NotIn`, `IsNull`, `IsNotNull`.

## Column operators

All column types share these common operators:

| Method | SQL |
|--------|-----|
| `col.Eq(val)` | `col = ?` |
| `col.NotEq(val)` | `col != ?` |
| `col.IsNull()` | `col IS NULL` |
| `col.IsNotNull()` | `col IS NOT NULL` |
| `col.In(vals...)` | `col IN (?, ?, ...)` |
| `col.NotIn(vals...)` | `col NOT IN (?, ?, ...)` |
| `col.InSub(subquery)` | `col IN (SELECT ...)` |

Numeric columns (`IntColumn`, `Int64Column`, `FloatColumn`, `Float32Column`, `AnyColumn`) also have:

| Method | SQL |
|--------|-----|
| `col.Gt(val)` | `col > ?` |
| `col.Gte(val)` | `col >= ?` |
| `col.Lt(val)` | `col < ?` |
| `col.Lte(val)` | `col <= ?` |
| `col.Between(min, max)` | `col BETWEEN ? AND ?` |

String columns have:

| Method | SQL |
|--------|-----|
| `col.Like(pattern)` | `col LIKE ?` |
| `col.ILike(pattern)` | `col ILIKE ?` |

## Nullable fields

Dew columns generate SQL — they don't control how Go scans the result. For nullable database columns, use `sql.Null*` types in your struct with the same column type in the schema:

```go
type User struct {
    ID    int
    Name  string
    Email sql.NullString // nullable in DB
    Age   sql.NullInt64  // nullable in DB
}

var Users = dew.DefineSchema("users", dew.PostgreSQLDialect{}, func(t dew.Table[User]) struct {
    dew.Table[User]
    ID    dew.IntColumn
    Name  dew.StringColumn
    Email dew.StringColumn // same column type — SQL doesn't change
    Age   dew.Int64Column  // same column type
} {
    // ...
})

// IsNull / IsNotNull work on every column type
Users.From(db).Where(Users.Email.IsNull()).All(ctx)
```

<Callout type="info">
No special `NullStringColumn` or `NullIntColumn` needed. Column types control SQL generation, struct field types control scanning — they're independent.
</Callout>

## Aliases

Use `.As()` to alias a column in SELECT queries:

```go
Users.From(db).Select(Users.Name.As("user_name"))
// SELECT name AS user_name FROM users
```

## NewTable

If you prefer not to use `DefineSchema`, create a table directly:

```go
table := dew.NewTable[User]("users", dew.PostgreSQLDialect{})
id := table.IntColumn("id")
name := table.StringColumn("name")
```
